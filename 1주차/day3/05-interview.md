## 1. Spread 문법은 깊은 복사를 수행하는가?

### 내 답변
- Spread 문법은 깊은 복사를 수행하지 않고 얕은 복사를 수행한다. 바깥 객체나 배열은 새로 만들어지지만, 중첩 객체는 기존 참조를 그대로 공유한다. 그래서 중첩 객체를 변경하면 원본에도 영향이 갈 수 있다.

### 체크 포인트

- Spread는 한 단계만 복사한다는 점
- 중첩 객체는 참조가 공유될 수 있다는 점
- 얕은 복사와 깊은 복사를 구분할 수 있어야 한다는 점
- 깊은 복사가 필요하면 변경 경로를 따라 새 객체를 만들거나 적절한 복사 API를 검토해야 한다는 점

## 2. React 상태를 직접 변경하면 왜 문제가 되는가?

### 내 답변
- React는 상태 업데이트 시 이전 상태와 다음 상태를 `Object.is`에 가까운 방식으로 비교한다. 객체나 배열 상태를 직접 변경한 뒤 같은 참조를 다시 `setState`에 전달하면 React는 변경이 없다고 판단해 렌더링을 생략할 수 있다. 그래서 기존 상태를 직접 변경하지 않고 새 객체나 새 배열을 만들어 `setState`에 전달해야 한다.

### 체크 포인트

- React 상태는 불변하게 다뤄야 한다는 점
- 객체와 배열은 내용이 아니라 참조가 비교된다는 점
- 같은 참조를 다시 전달하면 렌더링이 생략될 수 있다는 점
- 이전 상태 기반 업데이트는 함수형 업데이트가 안전하다는 점

## 3. `||`와 `??`의 차이는 무엇인가?

### 내 답변
- `||`는 Falsy한 값이 들어올 경우 우항의 값을 사용하고, `??`는 `null` 또는 `undefined`가 들어올 경우에만 우항의 값을 사용한다. 예를 들어 `page`가 `0`이면 `page || 1`은 `1`이 되지만, `page ?? 1`은 `0`이 된다.

### 체크 포인트

- `||`는 Falsy 전체를 기준으로 동작한다는 점
- `??`는 `null`과 `undefined`만 기준으로 동작한다는 점
- `0`, `""`, `false`가 유효한 값인지 먼저 판단해야 한다는 점
- 기본값 처리에서는 `??`가 의도를 더 정확히 표현하는 경우가 많다는 점

## 4. `sort()`와 `toSorted()`의 차이는 무엇인가?

### 내 답변
- `sort()`는 원본 배열을 직접 변경하고 같은 배열 참조를 반환한다. 반면 `toSorted()`는 원본 배열을 변경하지 않고 정렬된 새 배열을 반환한다. React 상태 배열을 정렬할 때는 `toSorted()`나 `[...array].sort()`처럼 새 배열을 만들어야 한다.

### 체크 포인트

- `sort()`는 원본을 변경하는 메서드라는 점
- `toSorted()`는 원본을 유지하고 새 배열을 반환한다는 점
- React 상태 배열에는 원본 변경 메서드를 직접 쓰지 않아야 한다는 점
- `toSorted` 지원 환경이 애매하면 복사 후 `sort`하는 대안이 있다는 점

## 5. 얕은 복사된 객체에서 중첩 객체 참조가 공유되는지 어떻게 확인할 수 있는가?

### 내 답변
- `Object.is` 또는 `===`로 바깥 객체와 중첩 객체의 참조가 같은지 비교할 수 있다. 얕은 복사를 하면 바깥 객체는 새로 만들어져 `Object.is(original, copied)`는 `false`가 되지만, 중첩 객체는 참조를 공유하므로 `Object.is(original.user, copied.user)`는 `true`가 될 수 있다.

### 체크 포인트

- `Object.is` 또는 `===`로 두 값이 같은 참조인지 비교할 수 있다는 점
- 얕은 복사는 바깥 객체 참조는 달라져도 중첩 객체 참조는 같을 수 있다는 점
- 예를 들어 `Object.is(original, copied)`는 `false`, `Object.is(original.user, copied.user)`는 `true`가 될 수 있다는 점
- React 상태에서는 변경되는 중첩 경로를 새로 복사해야 한다는 점
- `Object.is`는 깊은 비교가 아니라 같은 값 또는 같은 참조인지 확인하는 비교라는 점

## 6. `map` 안에서 부수효과만 실행하는 코드는 왜 피하는 것이 좋은가?

### 내 답변
- `map`은 각 요소를 변환해서 새 배열을 만들기 위한 메서드다. 그런데 반환값을 사용하지 않고 부수효과만 실행하면 코드의 의도가 흐려지고 불필요한 배열이 만들어진다. 새 배열이 필요하면 `map`을 사용하고, 각 요소마다 부수효과만 실행하는 목적이라면 `forEach`를 사용하는 편이 더 적절하다.

### 체크 포인트

- `map`은 새 배열 변환이 목적이라는 점
- 반환값을 사용하지 않는 `map`은 의도를 오해하게 만들 수 있다는 점
- 부수효과 실행이 목적이면 `forEach`가 더 적절하다는 점
- `filter`, `find`, `some`, `every`, `reduce`도 목적에 맞게 선택해야 한다는 점
