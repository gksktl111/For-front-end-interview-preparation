# 시맨틱 HTML과 접근성

## 시맨틱 HTML이란

시맨틱 HTML은 요소의 생김새가 아니라 의미와 역할에 맞는 태그를 사용하는 것이다.

```html
<main>
  <h1>클립 목록</h1>
  <section>
    <h2>최근 저장한 클립</h2>
    <button type="button">클립 복사</button>
  </section>
</main>
```

브라우저는 HTML을 단순한 문자열로만 다루지 않는다. 각 요소의 의미를 DOM, 접근성 트리, 기본 키보드 동작, 폼 동작 등에 반영한다.

## 의미에 맞는 요소 선택

| 필요한 기능 | 적절한 요소 | 이유 |
| --- | --- | --- |
| 현재 화면에서 동작 실행 | `button` | 기본 키보드 조작과 비활성화 상태를 제공한다 |
| 다른 위치로 이동 | `a` | 링크 역할과 이동 목적을 표현한다 |
| 사용자 입력 제출 | `form` | Enter 제출, 검증, 제출 이벤트 흐름을 제공한다 |
| 입력 항목 설명 | `label` | 입력 요소의 accessible name을 제공한다 |
| 문서 구조 제목 | `h1` ~ `h6` | 화면의 목차 구조를 만든다 |
| 주요 콘텐츠 영역 | `main` | 페이지의 핵심 콘텐츠를 구분한다 |
| 독립적인 콘텐츠 묶음 | `section`, `article` | 문서 구조를 명확히 만든다 |

## `button`과 `a`

`button`은 액션을 실행할 때 사용한다.

```tsx
<button type="button" onClick={handleCopy}>
  클립 복사
</button>
```

적합한 경우:

- 복사
- 삭제
- 저장
- 모달 열기
- 드롭다운 열기
- 현재 화면 상태 변경

`a`는 이동할 때 사용한다.

```tsx
<a href="/clips/123">클립 상세 보기</a>
```

적합한 경우:

- 내부 페이지 이동
- 외부 링크 이동
- 파일 다운로드
- 페이지 내 특정 섹션 이동

`a href="#"`에 클릭 핸들러만 붙여 버튼처럼 쓰는 방식은 피한다. 이동이 목적이 아니라면 `button`을 쓰는 것이 의미와 동작 모두 자연스럽다.

## `div role="button"`의 한계

다음 코드는 겉보기에는 버튼처럼 동작할 수 있다.

```tsx
<div role="button" tabIndex={0} onClick={handleCopy}>
  클립 복사
</div>
```

하지만 실제 버튼이 제공하는 기본 동작을 직접 구현해야 한다.

직접 처리해야 하는 것:

- Tab 포커스
- Enter 키 실행
- Space 키 실행
- 비활성화 상태
- 폼 안에서 제출되지 않게 하는 동작
- 포커스 스타일

권장 방식:

```tsx
<button type="button" onClick={handleCopy}>
  클립 복사
</button>
```

실제 `button`의 장점:

- 기본적으로 키보드 접근성이 있다.
- 접근성 트리에 버튼 역할로 노출된다.
- `disabled` 속성을 사용할 수 있다.
- 브라우저와 보조 기술이 기대하는 동작을 제공한다.

## ARIA보다 기본 HTML을 먼저 쓰는 이유

ARIA는 의미를 보완하는 도구다. 없는 동작을 자동으로 만들어주지 않는다.

```html
<div role="button">저장</div>
```

위 코드는 스크린 리더에 버튼 역할을 알려줄 수는 있지만, 실제 버튼의 키보드 동작을 자동으로 완성하지 않는다.

기준:

- 기본 HTML 요소로 표현할 수 있으면 기본 요소를 먼저 사용한다.
- HTML로 표현하기 어려운 복합 위젯에서만 ARIA를 보완적으로 사용한다.
- ARIA를 추가했다면 키보드 조작과 상태도 함께 구현해야 한다.

## Form, Label, Input

입력 요소는 어떤 값을 입력해야 하는지 명확히 연결되어야 한다.

```tsx
<form onSubmit={handleSubmit}>
  <label htmlFor="clip-title">클립 제목</label>
  <input id="clip-title" name="title" />
  <button type="submit">저장</button>
</form>
```

좋은 점:

- 라벨 클릭 시 입력 요소에 포커스가 이동한다.
- 스크린 리더가 입력 목적을 읽을 수 있다.
- 브라우저 기본 제출 흐름을 사용할 수 있다.
- 자동완성이나 검증을 연결하기 쉽다.

피해야 할 코드:

```tsx
<span>클립 제목</span>
<input name="title" />
```

화면상으로는 설명이 가까이 있어도 DOM상 연결이 없다. 보조 기술은 이 입력이 어떤 값인지 알기 어렵다.

## Heading 구조

Heading은 화면 글자 크기보다 문서 구조를 표현한다.

```html
<h1>대시보드</h1>
<h2>오늘의 클립</h2>
<h2>최근 활동</h2>
<h3>댓글</h3>
```

좋은 heading 구조:

- `h1`은 화면의 대표 제목으로 사용한다.
- 섹션이 나뉘면 `h2`를 사용한다.
- 하위 섹션은 `h3`처럼 단계적으로 내려간다.
- 시각적 크기는 CSS로 조절한다.

피해야 할 방식:

```html
<h1>설정</h1>
<h4>프로필</h4>
<h2>알림</h2>
```

문서 구조가 불규칙하면 키보드 사용자와 스크린 리더 사용자가 페이지 구조를 파악하기 어렵다.

## 기본 키보드 접근성

웹 UI는 마우스 없이도 주요 기능을 사용할 수 있어야 한다.

확인할 것:

- Tab 키로 대화형 요소에 도달할 수 있는가?
- 포커스가 어디 있는지 눈에 보이는가?
- Enter 또는 Space로 버튼을 실행할 수 있는가?
- Escape로 모달이나 메뉴를 닫을 수 있는가?
- 포커스가 모달 밖으로 무의미하게 빠지지 않는가?

실무에서는 스타일 초기화 과정에서 `outline: none`을 무조건 적용하지 않아야 한다. 포커스 표시를 지운다면 대체 포커스 스타일을 반드시 제공해야 한다.

## 면접 답변 핵심

시맨틱 HTML은 요소의 의미에 맞는 태그를 사용하는 것이다. 의미에 맞는 요소를 쓰면 브라우저가 기본 키보드 동작, 접근성 역할, 폼 동작을 제공하므로 사용성과 유지보수성이 좋아진다. ARIA는 기본 HTML을 대체하는 수단이 아니라, HTML만으로 표현하기 어려운 의미를 보완하는 수단이다.
