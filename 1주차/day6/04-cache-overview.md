# Cache 개요

## 이번 주의 학습 범위

브라우저 캐시, CDN, 재검증 전략은 웹 성능 주차에서 깊게 다룬다. Day 6에서는 HTTP 응답이 항상 매번 새로 다운로드되는 것이 아니며, 캐시 정책에 따라 재사용될 수 있다는 정도를 이해한다.

## Cache란

Cache는 이미 받은 응답을 일정 조건에서 재사용하는 장치다. 같은 리소스를 매번 네트워크로 다시 가져오지 않아도 되므로 속도와 비용을 줄일 수 있다.

```text
첫 요청
Browser → Server → Response 저장

다음 요청
Browser → Cache 재사용 또는 재검증 → 필요한 경우 Server 요청
```

캐시가 영향을 주는 것:

- 페이지 로딩 속도
- 이미지, CSS, JavaScript 다운로드 비용
- API 응답 재사용 여부
- 배포 후 사용자가 오래된 파일을 볼 가능성

## `Cache-Control`

`Cache-Control`은 응답을 얼마나, 어떤 방식으로 캐시할지 알려주는 Header다.

예:

```http
Cache-Control: max-age=3600
Cache-Control: no-cache
Cache-Control: no-store
```

간단한 의미:

| 값 | 의미 |
| --- | --- |
| `max-age=3600` | 3600초 동안 캐시를 신선한 상태로 봄 |
| `no-cache` | 캐시를 저장할 수 있지만 사용 전 재검증 필요 |
| `no-store` | 저장하지 않음 |

자세한 캐시 전략은 성능 주차에서 별도로 다룬다.

## ETag

ETag는 서버가 응답 버전을 식별하기 위해 내려주는 값이다.

```http
ETag: "clip-list-v1"
```

브라우저는 이후 요청에서 자신이 가진 버전을 서버에 알려줄 수 있다.

```http
If-None-Match: "clip-list-v1"
```

서버가 아직 같은 버전이라고 판단하면 전체 응답 대신 `304 Not Modified`를 보낼 수 있다.

핵심:

- ETag는 캐시 재검증에 사용된다.
- 데이터가 바뀌지 않았다면 전체 응답을 다시 받을 필요가 없다.
- 네트워크 비용을 줄이는 데 도움이 된다.

## CDN

CDN은 사용자와 가까운 위치에서 정적 파일이나 응답을 제공하는 네트워크다.

예:

- 이미지
- CSS
- JavaScript 번들
- 폰트
- 정적 HTML

CDN을 사용하면 원본 서버까지 매번 가지 않아도 되므로 응답 속도를 줄일 수 있다.

## 지금은 이 정도만 기억하기

- 캐시는 응답 재사용으로 네트워크 비용을 줄인다.
- `Cache-Control`은 캐시 정책을 알려주는 Header다.
- ETag는 응답 버전 비교와 재검증에 사용된다.
- CDN은 사용자 가까운 곳에서 파일을 제공해 속도를 개선한다.
- 잘못된 캐시 설정은 오래된 화면이나 오래된 API 응답 문제를 만들 수 있다.

## 면접 답변 핵심

캐시는 같은 리소스를 반복해서 다운로드하지 않도록 응답을 재사용하는 장치다. `Cache-Control`은 캐시 정책을 정하고, ETag는 서버와 브라우저가 응답 버전을 비교해 재검증할 때 사용된다. CDN은 사용자와 가까운 위치에서 정적 파일이나 응답을 제공해 네트워크 지연을 줄인다.
